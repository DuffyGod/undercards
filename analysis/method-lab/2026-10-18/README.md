## 做出的选择

主报价写为“已经施加的效果状态差额＋一个剩余身体价值”。身体F暂保留旧的capped-attack设计作为固定基线；本轮没有发明新身体函数。普通攻击、击杀和控制奖励不在账本外重复相加。`realized`对直接伤害是已兑现收益，对友军增攻/敌军减攻则是另一个对象当前状态的差额，并非永远不可追回。

抗惩罚先给两个端点与损失斜率：

`V(p) = V(no reply) - p * [V(no reply) - V(answered)]`

p是假设“持有、付得起且实际采取这一有效回应”的联合暴露程度，不是实测沉默率。报价已包含这次损失，不再加稳定性罚分、标准差罚分或CVaR。对手资源支出没有计入本轮账本，因此这是**条件资产回收值**，不是完整资源交换价值。回应作用于候选本体；其他对象被沉默、重新强化或移除，是不同的情境。

等待只给一次：现在选择打出、等到固定下一观察点，或最终不出。未来状态揭晓后可选择部署/放弃；当前不能先偷看未来。等待代价是显式外生的放弃收益假设，尚未由真实承伤与回合节奏推导。

这三块目前是独立试验：12张源卡结构探针、一次等待、同预算替换。**没有把实际12张牌接成携带价值或构筑排名。** 不为凑30–50张完整覆盖扩建机制执行器；下一步先检验这些价格关系是否有用。

## 实际结果

### 攻击边际

固定中心参数时，6/7→7/7为 **0.27617 model-G**，9/7→10/7为 **0.08260**。这复现旧F的边际形状，**不是本轮新增发现或校准证据**。本轮保存了3种face-share假设、720个身体状态的ATK+1与HP+1差值，便于下一步比较替代公式。

`E[min(A+1,H)-min(A,H)] = P(H>A)`，因此capped部分的边际由目标生命尾概率控制。总身体价值还含击杀/存活阈值，所以不能要求最终ATK边际处处递减；新临界线可以产生局部跳变。face-share .1/.2/.35和目标分布都是设计输入。

### 同费用牌在惩罚条件下可以翻转

共同输入：其他敌方为一个普通4/5、手牌打出后4张、其他友军为一个普通3/4。候选本体承受一次4伤；条件回应借用Punishment的3G/4伤文字，假设对手可取得且有6G。以下是扣部署成本之前的条件回收值：

| 4G候选 | 无此回应 | 本体遭4伤 | p=.25 | p=.5 |
| --- | ---: | ---: | ---: | ---: |
| Vulkin | 4.74749 | 1.12279 | 3.84131 | 2.93514 |
| Woshua | 4.20302 | 2.10057 | 3.67741 | 3.15180 |

交点 **p≈0.35767**。它证明此简单报价能区分端点回收结构，而非证明两牌真实强度排序。Vulkin只比较普通敌体/打脸的受限目标菜单；Woshua的减攻按当前敌体F差定价，后续场面与对手资源转化都未求解。没有增加卡名奖励。

Glyde与同6G的The Warrior另作旧问题回归。打出后手牌4张时，Glyde端点为6/6，沉默回2/2；Warrior保留已受5伤的7/4。沉默条件下交点 **p≈0.28516**；手牌3、5、6张时分别约.05782、.40170、.46226。该结果由同一成长/伤害结构计算，不反推“Glyde应该低多少”的参数。没有给Archer补写未实现完整价格。

### 一次等待及真实支付竞争

独立手算例：现在净收益2.5；等到下一观察点后收益等概率为1或5，放弃收益1，则等待值2，当前应选择2.5。若提前知道未来再决定现在/等待，会虚增为3.25，程序没有采用该算法。

同现金6、同一背景手牌X（费用4、声明净收益6）：候选C（费用6、净收益7）只能取得7；替代R（费用2、净收益2）可与X同时支付取得8，C相对R为−1。这里只检验净收益/付款菜单的机会成本，不代表真实卡牌组合的已校准收益。

## 数值边界

- F的6/5→5锚仅统一单位，不证明Aaron值5或零费牌非常强。margin未包含一次抽牌与卡位替换的完整成本，不能按该列跨费用排强度榜。
- Penetration、Punishment和Headshot来自不同条件回应面板，不宣称同一SOUL原生同时拥有全部法术。`response_access`与真实现金必须显式满足；回应只影响本体，敌方副产身体与已支出手牌/G均未入账。
- 只用数值普通目标；不追求全体卡牌机制闭合。12张结构探针不是当前主模型的新增完整支持数。复杂卡不因没有探针就价值0。
- F作为残值仍隐含未来发挥。这个启发式会漏掉即时保命、攻击频率、末回合压力、格子持续占用等；没有声称足以区分所有角色与阶段。
- Armor/Dodge仅用于独立条件伤害检查，不给完整关键词价格；二者同时存在的结算顺序被拒绝。受伤HP成长的沉默重置也不猜。
- 单次抽牌的.65净机会价格、打脸伤害的.25价格尚未校准。其他角色、牌库身份与疲劳不会从这里自动推导出来。
- 本轮参数区间不是统计置信区间；720个状态也不是720个实战样本。

## 文件及运行

标准库、Python3.11+。从仓库根运行：

```sh
python analysis/method-lab/2026-10-18/run_experiment.py
python -m unittest discover -s analysis/method-lab/2026-10-18 -p 'test_*.py' -v
```

已有`inputs.json`时只读取冻结输入；没有时从项目Skill快照提取小型输入。它保留快照SHA256、377个普通4–7G身体参考、12张源卡原文与设计参数。程序不导入旧评分器或云端代码。直接修改design会实际改变报价；原输入应另存以比较敏感度。

- `card-probes.csv/json`：12张条件结构探针，非榜单。
- `body-marginals.csv`：720个身体网格点。
- `risk-crossings.json`：风险交点与两端点。
- `synthetic-risk-grid.json`：28组抽象成长/已施加收益结构。
- `waiting-grid.json`：30个机会频率/放弃收益设计点。
- `diagnostics.json`：独立手算例和关键摘要。
- `verification.json`：本轮实际检查收据；不是实战正确率。
- `provenance.json`：输入/源码哈希与基线提交号。

两名独立子智能体给出了信息时序、同预算替换、伤害包与沉默反例，并只读审查原型。审查发现并修正：design只写入输出而未驱动计算；非法手数/目标数输入；本体沉默列易误读。没有新增模拟器或追求旧测试数量。

## 下一步的决策
