# 从部署报价到同槽位价值：第二轮统计估值

2026-10-18。本轮不改变既有身体F，也不补全对局引擎；改进的是**需求总体、联合敏感度、资源竞争与数值归因**。已交付可查询程序`quote_card.py`、共同参数压力试验、同一手牌槽替换的付款模型及可复算数据。

主要结论：原“受伤宽场Piranhas明显强于Car”不能外推到真正受2伤后的幸存状态；采用用户提出的Ice Cap/Vulkin身体需求，Piranhas又明显领先。通用公式必须对所有候选使用同一需求分布，并由该分布驱动价格。不能给每张牌各取最适合的情境，也不能把任意“低费卡池”直接称为快攻实战分布。

## 1. 主标准应进一步转向同一槽位的可实现增益

部署报价`S(c)=E[Q(c,s)]−cost(c)`可以敏感地描述单卡回收，但仅有S与“可支付且值得出就出”的机会指数I，仍未扣掉占据手牌槽的替代价值。特别是适用面窄的牌，不能在没被使用时总以免费0收益结束。

本轮实现一个有限、可解释的共同替换标准。固定现金G、可用格子K、敌场E、同一背景物理手牌H，令替换槽中为x：

`M_x = max_同一可支付物理菜单 [整个己方终点F + 敌方终点F下降 + 已兑现效果价 + λ·剩余Gold]`

`V_slot(c;r) = M_c − M_r`

候选c与共同参考r只占同一个槽；背景、现金、格子、价格完全相同。可不打候选，但若参考本来能补足一次支出，候选放在该槽里就可能产生**负替换价值**，不再免费忽略它占掉的机会。费用已通过实际付款进入M，不能在差额上再扣一次cost。

因此下一版通用卡组主分的形式应为`E_{s~D}[V_slot(c;r,s)]`，其中D是共同、可追溯的需求/资源/背景手牌分布。部署S、固定行动属性边际及使用质量作为诊断列。尚未取得某副卡组的D，就不能给它伪造一个已校准的构筑单分；本轮实现的是局部菜单下可比较的原型。

本轮菜单只含真正无效果背景身体。它们被分成候选前出、候选后出、不出三组，无须排列同组内部顺序。候选效果、即时攻击及整个背景选择先固定，随后对随机连锁积分；不会把每张卡在初始局面的独立最优值相加。候选结算时手牌数按已真实打出的前缀扣除。

## 2. 付款与格子的实际数值

背景固定为Froggit(2G)、Candy Dish(3G)、Aaron(5G)，共同参考为槽位内另一张Froggit。敌方三个3/2。下表λ=0，即只评价当前截止资产，剩余现金不在这一目标中报价。

| 状态 | 候选菜单M | 参考菜单M | 槽位差 | 固定原菜单+1ATK |
| --- | ---: | ---: | ---: | ---: |
| Vulkin，6G、2格 | 8.023 | 5.687 | +2.335 | +0.414 |
| Vulkin，6G、1格 | 5.785 | 5.000 | +0.785 | 同样可逐菜单计算 |
| Archer，4G、1格 | 3.449 | 3.449 | 0 | 0 |
| Archer，4G、2格 | 3.449 | 4.476 | −1.027 | 0 |

第一行候选用Magic移除一个3/2，与背景Froggit共出；参考侧只能选背景Froggit+Candy Dish。Vulkin多1攻击，沿用原菜单仍提高0.414，不需要发生打法改变。只剩1格时，参考改选Aaron，改变的是共同支出竞争。

Archer在4G付不起。1格时两侧都选Candy Dish；2格时参考侧能出两只Froggit，候选侧不能，故候选占槽造成−1.027。再多1G，两侧都能出Froggit+Candy Dish，差额回到0。**替换分不要求随现金或格子单调**，参考也会从资源增加中受益。

另一个真实平台：6G、1格、空场，初始4张手牌的Glyde最多成长5/5；背景Aaron为6/5且更便宜。两侧都选Aaron，Glyde+1ATK只追平，槽位增量仍0。其潜在部署身体价格仍增加；“单卡数值提高”与“这一资源条件下最高可实现收益提高”是两个应并列的量，不应强行用任意奖金消除平台。

模型也扫描λ=.5/1。λ=1给留存Gold完整价格；λ=0只表达当前截止需求，不能称真实Gold没有长期价值。增加1G的M边际包含基础留存价λ及新增付款机会；查询程序将后者单列为`cash_opportunity_gain_above_residual`。

再固定8G、2格、λ=1及上述三张背景，在同一32个低费三体样本上得到：

| 候选 | 相对Froggit的槽位均值 | 数值抽样SE | 严格增加背景最优收益的样本质量 |
| --- | ---: | ---: | ---: |
| Piranhas | +0.864 | 0.113 | 87.5% |
| Archer | +0.677 | 0.140 | 50.0% |
| Blockler B | +0.203 | 0.078 | 18.75% |
| Vulkin | +0.993 | 0.068 | 100% |

Piranhas−Archer均差0.187、配对SE0.184，不能据此稳排先后。增加一个空格时，Archer侧最高可实现值增加0.398，相对参考的槽位差增加0.159；Piranhas侧最高值不变，但参考可多获得一份背景收益，其相对差反降0.238。格子已通过真实替代进入价格，不另加“占格罚分”。这些仍是当前窗口、tail=0的条件报价，不能当含未来能力的整卡排名。

## 3. 受伤总体修正了上一轮结论

本轮复用同一512个原始三体板，比较原始、clamp受伤及真实AOE2后幸存状态。前置AOE属于共同背景，不能把它的伤害记到候选收益。真实幸存版删除HP≤0的身体，**保留空场及原始权重**。

这里的伤害变换只作用于普通数字身体，没有为卡池原卡执行其Armor、Dodge、Dust等效果；“真实幸存”指按2伤移除这些普通目标，不等同完整实战AOE结算。

| 共同需求 | Car − Piranhas的中央净报价差 | 配对数值抽样标准误 |
| --- | ---: | ---: |
| 费用层等权原始三体 | +0.536 | 0.0425 |
| 同板max(1,H−2) | −0.690 | 0.0428 |
| 同板真正H−2、移除死体 | −0.090 | 0.0380 |
| 卡等权原始三体 | +0.472 | 0.0389 |
| Ice Cap/Vulkin身体各半 | −2.656 | 精确积分，无此抽样误差 |

clamp把本来HP≤2的42.80%需求也变成1HP，制造了额外连锁燃料。真实AOE2后，原三体平均剩约1.72体；当前样本空场占7.03%。由clamp改成真实幸存状态，Car−Piranhas增加0.600，变化的配对标准误仅0.0357。这是需求假设的实质影响，不能用增加同类clamp样本修复。

旧报告的受伤面板仍作为`clamp_diagnostic`保留。它表示一种特定的存活需求变换，不再作为真实AOE2后的替身。本轮同板clamp与旧报告独立抽样的wounded_wide数值略有不同，不能把抽样差也解释成模型修正。

## 4. 联合参数，而非逐个调参后称稳定

单因素扫描不考察交互作用；本轮采用4因素两水平的16个联合组合，加中心，共17点。参数仍为既有范围：攻击打脸份额.1/.35、身体阈值价.2/.6、未来储备tail=0/1、直接伤脸价.15/.4。没有用卡牌排名重新挑范围。这一设计参考[NIST单因素局限](https://www.itl.nist.gov/div898/handbook/pri/section2/pri212.htm)和[NIST全因子设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri333.htm)；采用方法不意味着参数已获游戏数据验证。

每一点对全部19卡使用同一θ，所有属性小改也配对计算。1938行共同需求结果，另有323行IceCap/Vulkin精确需求结果。

| 共同需求 | Car − Piranhas：17点范围 | Glyde − Archer：17点范围 |
| --- | ---: | ---: |
| 费用层等权原始三体 | [+0.244,+0.641] | [−2.225,−1.319] |
| 中费单体 | [−1.478,−0.492] | [−0.646,−0.287] |
| 高费单体＋沉默 | [−1.275,−0.978] | [−1.373,−1.049] |
| 真实AOE2幸存 | [−0.649,+0.112] | [−1.129,−0.371] |
| 空场发展 | [−2.661,+0.826] | [+1.530,+1.970] |
| IceCap/Vulkin身体 | [−2.766,−2.529] | [−2.032,−1.198] |

所以真实幸存总体下，Car/Piranhas的**部署净报价S排序不稳**；但机会指数I的配对差在这17点均仍为负，不能把S的反转也说成I反转。两者不同在于I只累计可支付且正净收益的部署机会；I也因此不能代替已经扣除共同槽位替代损失的V_slot。

这些范围只覆盖17个有限压力点，不是连续参数盒的全局界或实战置信区间。IceCap/Vulkin板可按0–3个Vulkin压缩成4个二项计数状态；所有8种有序板的报价与属性边际已独立核对。这个需求仅使用已在场的3/1、4/4数字身体，未计算其入场伤脸或我方生存。

## 5. 攻击边际由需求的击杀线驱动

| 卡牌 | 原始低费三体+1ATK | IceCap/Vulkin三体+1ATK | 后者固定原行动+1ATK |
| --- | ---: | ---: | ---: |
| Blockler B | +0.616 | +1.637 | +1.612 |
| Piranhas | +0.854 | +0.419 | +0.419 |
| Broken Car | +0.949 | +1.727 | +0.685 |

在1HP/4HP需求中，Piranhas已有4ATK，升到5不再开启新的目标击杀线。B的3→4却跨过Vulkin身体门槛，沿用原攻击也得到大幅增值。Car的3→4除固定行动数值变化外，还允许改选另一个4HP目标，以Magic与攻击分开处理；这部分重新优化增益约1.042。

对共同原始三体，Woshua的+1ATK在17点中为0.517–0.592，固定原行动相同；Car为0.942–0.955，固定原行动部分为0.630–0.710。这就是同一模型中可比较、对数值小改敏感的报价，不是按机制标签给牌分级。

## 6. 不强制所有属性增量为正

在低未来储备条件，Blockler B多1HP可推迟Dust兑现。例：敌方为4/3、1/1、2/1，B攻击同一4/3：

- 原3/4互杀，当前留下O4/3。
- 加HP成3/5后留下B3/1，Dust仍在，但O尚未召唤。
- 参数为ε=.35、阈值=.6、tail=0、伤脸价=.15，另有10%可选2伤回应，Q由5.652降至4.289。对手可以拒绝伤害B，不必帮助它触发Dust。

身体函数本身仍有`F(3,5)>F(3,4)`。负增量来自当前死亡路径与截止假设；不能外推为实战加HP必定有害。原始三体上这一参数点的平均+HP约−0.011；IceCap/Vulkin需求下低储备情形可更明显。模型需要能指出这种反例，而不是为保持全局单调性删去机制的数值后果。

## 7. 用收益差处理等价行动，弃用名称变化率作策略证据

同价值目标可能有不同的行动名称，浮点求和顺序也可能改变哪个标签先被选中。IceCap/Vulkin的4计数板与8有序板报价一致，但Archer的“计划名称改变质量”并不一致。它不能当作真实策略切换概率。

现在查询保留原固定行动的数值差，并在精确需求中新增：所有基准最优行动的+ATK增量范围，以及`mandatory_reoptimization_gain`。后者为重新最优增量减去基准最优集合内可实现的最大增量。这样，换一个等价行动标签不会制造“必须改打法”的收益。

卡槽菜单也区分确定性选择出的使用率与`M_candidate > M_background_only`的严格增益质量；零增益等价解不再制造伪使用率。更换共同参考Froggit为Moldsmal仅平移共同零点，候选两两分差在相同状态下不变，不能把参考替换当成另一项排名稳健性验证。

## 8. 当前可用程序与明确边界

```powershell
# 同一需求下的净报价、联合参数范围、配对属性边际、两牌共同参数分差
python -B analysis/method-lab/2026-10-18/quote_card.py --ids 649 530 --profile aoe2_survivors
python -B analysis/method-lab/2026-10-18/quote_card.py --ids 469 530 649 --profile icecap_vulkin

# 增加一个确切现金/格子/背景菜单下的同槽替换报价
python -B analysis/method-lab/2026-10-18/quote_card.py --ids 530 984 469 20 --slot --cash 8 --slots 2 --cash-residual 1
```

查询不会默认平均不同对手总体、现金或格子档；IceCap/Vulkin采用精确需求，aggro_32菜单的均值附数值抽样标准误。缺少支持的候选/状态会报错，不补0分。`round2-query-examples.json`冻结了5组查询实例。

卡槽部分已覆盖15候选、3个实际背景菜单、3个手算敌板，主菜单另有32个共同抽样板。现金4/6/8/10、空格1/2/4、λ=0/.5/1，共22,140条主参考记录。完整记录以确定性gzip交付；summary只作设计网格汇总，不能冒充某卡组的实战期望。

该局部菜单固定tail=0、无对手回应、未使用手牌在截止后不报价。Lesser Dog与Dodge等未来能力在此会丢失差异；其部署报价与储备敏感度仍保留在另一层。Broken Car、Snowdrake、Bench暂不接入背景菜单，避免漏掉友军数量、增益对象或抽后付款；这不是其价值为0。格子不足时Archer召唤失败是显式假设；现有共同惰性占位与背景不会自行攻击。

需要继续获得的关键统计依旧是：实际需求A/HP联合分布、现金/手牌/空格与持牌时点的联合分布、截止后的手牌/现金实际兑现、有效回应与对手支出。先用这些数据校准共同分布及少数续存价格，再扩大候选类型；不以追逐机制全覆盖作为本阶段主线。

## 9. 复核与交付

39项检查实际通过；475个原中心结果标量复现至1e−9以内。独立复核覆盖真实AOE删除、空场保重、费用竞争、格子、手牌成长、死亡产物、随机计划顺序、负HP物理锚、等价行动、替代参考查询。替代参考档未计算的属性边际返回None，不补0。手数无关机制采用精确统计压缩，保留现金与联合权重；独立对照1216个数值无差异，没有以性能优化替换模型。

四个生产包源码/输入SHA、两个压缩包的解压哈希、查询实例及负HP反例均由`round2_summary.py`核查并写入`round2-verification.json`。测试与哈希验证不等于实战Gold校准。

本轮沿用Undercards快照与旧研究证据，只新增/更新本研究目录，未修改旧价格内核、恢复材料或云端开发路径。未调用DeepSeek增加定价先验；两名子智能体分别独立实现需求压力与付款菜单，再交叉核查数值与边界。
