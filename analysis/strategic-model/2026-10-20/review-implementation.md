## 需要正式批次前修正的策略条件错误

**位置：`decide`的mutual筛选，首次审查约179行。**

```python
mutual=[e for e in v.enemy if u.a>=e.h and e.a>=u.a]
```

判断双方互死，应比较敌ATK与己当前HP，而不是与己ATK；后半条件应为`e.a>=u.h`。当前写法会遗漏一类真实可执行的互死清理，尤其影响受罚后残血anchor。

独立反例：己方英雄10HP，已有ready的5/2 anchor，无手牌；敌2/2 small、英雄30HP。safe条件`2>2`为假，错误mutual条件`2>=5`也为假，因此trade策略实际返回：

```text
('attack', 0, -1)  # 打敌英雄，留下2攻敌怪
```

若按真正互死条件，5攻足以杀2HP目标，2反击也足以杀己2HP，存在双方清掉的合法trade动作。这不证明每种目标下互死必然优于打脸；问题是名为trade的全策略池共有一个与实际HP不一致的筛选错误。它可能污染当前要比较的恢复、受罚残体与压力策略差异。已立即通知主Agent，建议保存该探针为新回归检查。

## 收入投影与实际引擎不一致

**位置：`decide`约195行与`act_turn`约305行。**

公开现金风险预测使用`min(next_enemy,10)`，而真实INTEGRITY第11回合起收入为11。默认5G回应一般不会因此改变是否可支付，但可参数化费用的试验会受影响。

独立探针：INTEGRITY，回应费用11G；敌已完成己第10回合、余额0，私手真的有回应。当前我方有两个2/2、现金2G、手中另一个small，采用guard_two。错误投影认为敌下次只有10G，所以允许部署第三个小体。实际执行敌下一回合，收入11G并立即清掉三只。输出为：

```text
income_projection_probe ('play', 10, -1)
actual_next_income 11 actual_response_casts 1 A_surviving_units 0
```

应将实际自然收入与策略中的公开收入预测复用同一规则。当前预测无需假装能知道未来私手施法或额外收益，但确定公开的SOUL基础收入不应丢失。此项亦已通知主Agent。

## 所查其他路径及解释边界

| 检查范围 | 实现所支持的判断 | 尚需注意的边界 |
|---|---|---|
| 初始资源、自然抽与现金留存 | 每人初始1G与三张起手；本方回合先按真实座次领收入、自然抽；未花现金不重置。`first_draw`明确区分首回合约定。 | 第11回合INTEGRITY预测差异见上。Kindness/Integrity是抽象中明确支持的两种被动，不可称已覆盖所有SOUL。 |
| 无威胁时guard是否关闭 | `enemy_response_unseen==0`或公开下一收入仍付不起时，`reserve=0`，不走fragile宽度和现金保留分支。guard_two与commit其余字段相同，应在这些相同世界逐动作一致。 | bank_rebuild的`order='durable'`一直存在，无威胁也仍偏厚体；不能宣称所有保守策略都完全退化为commit。它同时改变多个策略因素。 |
| 隐藏信息边界 | View不含敌手牌/牌序/RNG；未见回应数来自声明组成总数减已公开使用/烧毁数。当前decide没有直接检查敌私手。 | 这是“公开可能性”启发式，不是行为后验。回应烧毁身份被视为公开，是本抽象的观测假设。 |
| 回应真实支付 | decide只有己私手存在回应且当前现金够才尝试，play实际移除牌并扣费；群伤保留身体的实际剩余HP。 | 危险覆盖只检查`incoming>=hp and removed>0`，并没有保证施法后就脱离致死。这是启发式，不能称已完成保命搜索。 |
| 先削血再攻击 | setup_trade允许某个ready攻击者原来杀不了、伤害后能杀且能存活时先施法；施法后的下次decide会以新HP选择实际攻击。新test已含5/7对5/7的例子。 | finishes计数可能让同一ready单位同时“能够处理”多个敌怪；当前setup_trade阈值1不因此虚增到达阈值。若后续组合`combo_response=True`与阈值2/3，应做攻击者唯一使用分配。它也未涵盖伤害后需要互死或多次攻击合杀的全部路线。 |
| ready与召唤延迟 | 新部署Unit默认ready=False；只有下次本方回合开始才置True，敌回合不会使其就绪；attack再次将其置False。 | 本抽象没有Haste等即时干预；不能由它推导真实所有低费/高费怪的时机。 |
| 受罚后的部署/攻击计时 | 首次造成击杀的惩罚登记受罚者自己的turn钟；之后新部署uid记录再部署，只有它后续实际attack才记恢复攻击。先手/后手的caster turn没有混用。 | 首次仅削血零击杀不被计作first_effective_penalty；因此指标准确含义是“首次被回应杀死单位后”，不是所有受到惩罚后的恢复。未恢复和已经死亡样本需保留，不能从分母删掉。 |
| 资源保留范围 | reserve_gold约束当前身体候选；现金仍真实可用，draw/heal/response各自按其策略条件支付。 | 这不等于始终冻结2G。若报告说“保留2G重建”，需说明它是身体部署规则，其他资源转换仍会消费这笔钱。 |
| 零回应控制 | counts_for把回应份数转成small，保证25张且公开未见回应数为0。 | 它同时改变组成，不能将“无回应世界vs正常世界”的全部差值解释为单一回应效果。用于同一无回应世界内比较guard_two与commit的负控制是合适的。 |
| 胜负与截止 | 实际HP≤0停，未决单列；deadline_life_margin明确是期限目标，而非猜赢家。 | 期限生命差仍不能等同整局胜率。结构/策略选择依赖这一临时效用时需要公开。 |
