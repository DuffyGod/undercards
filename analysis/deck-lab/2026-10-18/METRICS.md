# 牌组结构指标：精确概率，不进行对局模拟

来源为2026-10-05 Undercards快照及旧经济研究的基础收入、余额留存规则。
Bookshelf #466：6G 4/6 EPIC；剩余牌库无非Generated法术时，选择本SOUL法术加入手牌并减2费。
Librarian #185：5G 4/4 RARE；剩余牌库无非Generated同名重复时，抽3并把3随机牌加库、后者减1费。
Bookshelf最多2张、Librarian最多3张；这些是构筑上限，分析器不会替代完整合法性审核。

`deck_metrics.py`把以下三个对象分开，避免以廉价统计伪装对局模型：

1. **移出初始牌库的n张均匀无放回样本**：精确超几何见牌率，以及剩余牌库的Need状态。看见不等于还握在手中，也不保证没被满手Erase。
2. **当前h张均匀随机手牌的费用探针**：精确计算至少一张可支付、至少两张合计可支付。它不是依据出牌策略筛选后的真实剩余手牌；目标、格子、攻击、组合顺序均另计。
3. **声明支出前缀下的金币**：双方初始1G，逐己方回合领取收入，余额留存。省略支出为0，是攒钱上界，不是建议打法；不计SOUL、神器、额外收入和减费。

起手3张有Wiki证据，但首回合抽牌例外、换回排除及完整重抽顺序尚未确认。
因此程序要求显式提供seen/hand/turn网格，不假定首回合抽几张，不模拟重抽。若使用起手3张，分别将首回合抽0/1张写成不同seen进度，不能把两者平均成真实概率。

最关键的Need细节：初始仅两张Librarian重复时，只要一张已从库中取出，剩库不再有该重复，条件概率为1；若还有另一对重复，必须额外移出那一对至少一张。
程序按每个名字的物理副本数精确卷积，同时返回无条件Need、已见Librarian、两者联合及条件概率，绝不将不同重复组的事件误当独立。
生成牌不进入初始非Generated计数；生成牌加入、抽牌顺序、此前已打Librarian造成的库变动不在本随机样本实验内。

**双Bookshelf本身也会阻塞Librarian。** 以下均为25张初始牌、其余名字全单例、无重抽的物理样本；列为“已见Librarian且剩库Need满足”的联合概率，非施放概率：

| 已从初始牌库移出 | 仅2 Librarian重复 | 2 Librarian＋另一重复对（如2 Bookshelf） | 仅3 Librarian重复 |
| --- | ---: | ---: | ---: |
| 3 | 23.00% | 3.83% | 2.91% |
| 5 | 36.67% | 11.63% | 9.13% |
| 7 | 49.00% | 22.19% | 17.96% |
| 9 | 60.00% | 34.39% | 28.70% |

这些差异只能与重复高质量牌的见牌收益并列权衡，不能直接换成Gold扣分。

互动卡由调用者用ID声明，不自动将某个机制等同“高质量”。比较去重方案时同时看：互动至少见1/2张、Bookshelf见牌、Librarian已见且Need就绪；不要把条件Need改善冒充实际抽到Librarian的概率改善。

牌表文件格式：

```json
{"counts":{"466":2,"185":2,"其他卡ID":1},"interaction_ids":[20,649,984]}
```

counts需合计25；示意省略处应补成实际牌表。执行例（网格是显式假设）：

```powershell
python -B analysis/deck-lab/2026-10-18/deck_metrics.py --deck deck.json --seen 3 4 5 7 9 --hands 3 4 5 6 --turns 1 2 3 4 5 --output metrics.json
python -B -m unittest discover -s analysis/deck-lab/2026-10-18 -p test_deck_metrics.py -v
```

`--spending 2 2`表示第1、2个己方回合固定支付2G；后续声明为不支出。程序逐回合检查支付合法性。
默认将先后手分列，绝不把先后手、seen或hand档位数当概率。
费用可支付是一种必要资源条件，不能直接变成实战使用率或胜率。
