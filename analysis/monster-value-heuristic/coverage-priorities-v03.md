# 4–8G 普通怪物机制覆盖扩展优先级

日期：2026-10-08。只读统计本地快照、现有解析器和保存的语义复核；未调用 LLM/API，未改主模型、价格或语义批次，未运行完整对局模拟。优先级依据重复文本、共用执行基础与实现成本，不依据具名单卡的预期排名。

## 统计口径与当前边界

母集限定 `card_type=monster`、`pool_category=ordinary_non_token`、`4<=cost<=8`，共 **404 张**；4/5/6/7/8G 分别 **131/95/97/54/27**。快照 SHA-256：`7f19bef22de440abf1c2273806acecd0447e8341ad12f10eb63b418dfad45b85`。

保存的 `context-pool-v03.json`（version `context-ledger-0.3.1`）为 **16 supported_heuristic、388 partial**；文件 SHA-256：`751d4c654e0f4e1c2fe808ea1dc20f48f33c3d148415512333b399b0eeeafb47`。这 16 是有完整模板的条件部署诊断，不是 16 张完整实战价格。

审查时工作树正在升级为 `context-ledger-0.4.0`。新增定量单目标/手牌数/其他怪物数伤害、条件 Haste 后，现场 `parse` 盘点得到 **17 无 unknown、387 仍有 unknown**；其中 984 仅解析到 Magic 的 `target_damage`，Bullseye 仍明确 partial。最终盘点读前/读后源码 SHA 相同：`3976f01752af039eed99af49fa7f4be67e4dc445ab07c51c7c11d1a7f3cbf325`。旧 v03 成品与工作树是两个版本，不能把新解析数填进旧成品。这个现场解析数也不自动意味着新增项已经完成数值回归。

下文“家族涉及数”是**不同卡的文字或字段命中数**，不是模块数、实战触发频率或新增完整覆盖数。家族会重叠，不能相加。`keyword_mentions` 可能是赋给对象或提及另一张牌的关键词；主体固有状态另查 `base_statuses`。

## 推荐执行顺序

### P0：先建立有限的对象、条件与事件依赖层

**覆盖入口：Need33、If52、Switch12、选择器34，存在重叠。成本中；主要障碍是缺输入与绑定，不是都缺规则裁定。**

先增有限 recipient/zone、固定筛选器、选择器、guard 所属对象、数量模式 `exact/up_to`、事件输出 ID。没有这些层，Add96、Summon65 和属性61 即使分词成功，也只能得到无法安全执行的片段。

适合首先落地的重复谓词：

- `Need: You spent GOLD on spells last turn.`：**5 张**（239、438、582、584、911）。输入是实际付出 G>0，不能以“施放过法术”代替；免费法术也不能凭名字让 Need 成立。
- `Need: Your deck has no non-Generated duplicates.`：**3 张**（185、503、533）；按当下剩余牌库、Generated 过滤和 ID 计数，不检查初始构筑名单。
- 当前牌库无非 Generated RARE/EPIC：**2 张**（274、297）；无非 Generated 法术：**2 张**（466、468）。统一字段和谓词可以复用，谓词成立不表示其后 Magic 已完整定价。

典型不需要新裁定的绑定缺口：153 的手牌≤5门；658 的 Generated 过滤；812 “Kill an ally monster to draw 2 cards” 的成功代价；984 输出为指定 2/3 的属性覆写。典型确有裁定问题：910 的 `unique COST` 指不同费用种数还是仅出现一次的费用。二者必须分开标记，不把明确漏字段包装成规则未知。

**验收：**每个谓词真/假、空目标、边界数、Generated/非 Generated 均有确定性反例；“未知输入”不能按 true 处理。整组分支共同变化；同一目标、同一实际成功事件和其输出在后续步骤继续使用。仍缺字段的模块保持 non-executable，完整卡继续 partial。

### P1：固定属性变化＋状态组合的共同末状态

**家族61，固定动作句19，严格简单 Magic 全句4；成本低到中。**

典型文本：11 `Magic: Give an ally monster +2 ATK.`；556 `Taunt. Magic: Give all other ally monsters +2 ATK.`；174 `Taunt. Magic: Gain +1 HP for each enemy monster.`。扩展应按同一身材函数计算修改后的最终身体差，联合 ATK/HP 与 Haste/Taunt/Armor/Dodge 进入同一个窗口，不能分别加“buff 身体收益”和“强化后完整身体收益”。

19 个固定属性动作入口：**11、13、23、103、143、148、202、247、278、307、396、438、556、612、669、762、773、802、968**。很多只是部分动作；例如 103 还须检查“0 ATK 时 kill”，148 后续生成费用来自被减后的同一目标，802 有分支和 copy 输出。简单 fullmatch 集合仅 **11、13、23、556**，前三张已支持，因此最保守的近期新增不是 19 张完整卡，而是首先解除 556 这类共同状态组合的执行障碍。

**裁定/输入边界：**202 的 `Give yourself +5 HP` 是玩家 HP 变化，不能当主体 +5 HP；heal 与增加最大 HP 分开；受伤目标、base/current 属性、clamp 以及沉默恢复方式需显式。未受伤合成目标可先成为声明过的窄域，但不能据此外推受伤目标。

**验收：**同一已知目标取一次联合差值；全体且 `other` 排除主体；强制只能点敌方时保留负收益；敌方减少与自身增加若来自同一目标，不各自挑不同的最优目标。

### P1：固定引用召唤及实际数量、拥有者、输出状态

**Summon65；固定引用动作24；单一完整 Magic4、Dust4。成本中；大多语义明示，依赖牌和生命周期是主要阻碍。**

24 个固定引用动作入口：**36、108、112、119、141、165、169、170、235、282、296、298、424、426、674、815、835、845、862、872、952、965、974、984**。该数排除了单纯“在你召唤时”一类触发语句，仍包含被 Need、Synergy、额外触发或后续修饰限制的片段。

直接 Magic 全句：169 `Summon a Bun [#357]`；170 `Summon 3 Star [#706]`；282 给对方召唤 Petrified Monster739；862 给对方召唤两个 Arcade Bat863。直接 Dust 全句：108 Pebble352；112 给对方 Ice10；235 两只 Kid Slime370；426 Rabbick298。

这些不是八个同价无文本 token：357 有 Dust 给 Bunbun +3 ATK；706 有 Haste、回合末 Die、Dust 治疗；739 有 Disarmed、自毁和对方全体伤害；10 有 Taunt 与 Dust Paralyze 击杀者；298 自身还有 Turbo/Dust。只有 370 真正空文字；352 仅 Taunt，适合先验证窄域。依赖注册表必须读到引用牌文本，不能以引用身材代替完整输出能力。

**裁定/输入边界：**效果 Summon 不自动触发 Magic；实际数量受四格限制；对手召唤收益反向计。普通死去→腾格→Dust 的队列及多输出顺序尚未完整验证，有限事件夹具需明确顺序假设。指定基础身材、当前覆写、Charge/Haste 等修饰必须绑实际输出，不能把 984 的指定 2/3 当印刷 1/1，也不能把 757 上限9当实际擦除9。

**验收：**0/1/多空格、对方获得、失败召唤、同次输出修饰和自毁均有反例；身体/Dust 收益只计一次；输出文字未支持时整卡仍 partial。这一通用家族与同窗伤害/Bullseye可共享事件基础，不应只为某一张卡写回调。

### P2：Draw 的可选数量、双边与过滤

**Draw33；有限数量入口21；简单完整 Magic3。成本低到中；纯数量清楚，牌库过滤和未来报价需要新增输入。**

最短近期入口是 44 `Taunt. Magic: Draw up to 2 cards.` 与 199 `Magic: Both players draw 2 cards.`，243 已支持。双边抽牌全族 **3 张**（154、199、809）；154 是直到六张，809 抽出的双方怪物随后可交换，不能都执行成各抽2。数量入口21张包含其他触发，不能据此宣称完整支持21。

**裁定/输入边界：**Draw 与 Add 分开，Turbo 只按实际 Draw；必须有双方手牌空间、牌库可用量、实际保留/烧牌和疲劳的作用域。过滤抽牌（牌类、部族、费用、最贵等）不能按任意抽牌一律收费。抽牌净选项先验可以复用，但不得加整张牌身材后又不支付它的未来费用；没有质量分布时须保留先验标签。

**验收：**`up to` 包括0，满手不免费获得资源，双方数量单独计算，空库反例可降为非报价结果；未知牌在抽到前不用于当前择优。只覆盖数量与空间不表示已支持所有抽牌后附加效果。

### P2：费用增减与统一已知手牌支付前沿

**严格明示费用增减45；简单自己的手牌费用动作8；成本中。**

典型：161 `Magic: Give 2 random spells in your hand -2 COST.`；645 满足 Need 后全部手牌−3；846 双方最高费各−4；847 对手顶三选一+2。现有 `payment_frontier` 可复用实际支付节省＋被解锁行动净收益，不需要另给自由 Gold 权重。

自己的手牌费用动作入口 **27、43、161、279、395、645、673、767**；43 已支持。明确费用增减45包含生成输出、牌库加费、base cost、返回和条件降费；完整简单手牌模板只有43、161。因此建议先扩 selector/eligible subset 后处理161，而不是宣布45个完整结果。

**裁定/输入边界：**SPELL/non-TOKEN/Turbo 等过滤需要手牌身份；随机选2枚举合法子集并平均，不能挑最大省钱两张。双方最高费用先明确并列目标；+COST 是对手未来支付变化，不是己方现金收入。当前费用、基础费用与支付底线分开，Whimsalot 的身体代价与 min1 不能漏掉。

**验收：**未使用牌省钱0；0费牌不按面额−2赠2G；选择后的 body/cost 变更留在同一输出；双方收益、费用增加和负净变化完整计账。没有显式未来报价和使用窗口时，只给受限支付诊断。

### P3：一次具名事件窗口，先 Dust，再 Delay/回合起止

**Dust47、Delay22、Turn start19、Turn end17；另 Shock13、Turbo9、Support7、Bullseye9。成本中到高。**

各数来自快照 keyword mentions，包括联合触发；例如301同时起止交换属性，不能把 Turn start 的整句正则漏掉它。`Magic/Dust/Turn start/...` 联合触发文本入口16张，说明统一 trigger set 比不断添加单条正则更有复用价值。

最安全的下一步是把固定身体修改、抽牌和固定引用输出绑定**一次显式事件**，不是为每张卡猜平均发动次数。47 张 Dust 中至少22张含 Add/Summon 数量动作入口，但多数另有生命周期，因此一次事件支持也不是47张全价。

典型：307 `Turn start: Gain +1 ATK.`；141 回合末召唤 Gift；909 Support 增长后关闭、Shock 重新开启；908 Support 最多抽1、Shock 降顶怪费用。Support 在友军攻击前，Shock 看施法基础费用，Need 查当前区域；Delay 不是简单“主体存活才发动”。

**裁定障碍：**复杂开始队列、连续随机链、互触发、同时死亡/触发和跨区身份需要更细规则，不能让“平均一次”掩盖它们。事件发生频率和沉默/非死亡移除权重仍是声明先验，不从语义 annotations 得到概率。

**验收：**事件身份、拥有者、实际数量、关闭/重开状态及主体/目标存活对象明确；Dust 与 Erase 分离；原主体离场不能一律取消 Delay；未覆盖的后续触发留 partial。无需整局模拟器，可以先固定一到两个事件窗口。

### P3/P4：位置、随机、复制、跨区与复合控制

**位置/选择器34、Random54、copy/copies27、Turn…into9、Erase14、明确 Kill 动词9、Silence 动词8。成本高，分成窄域再推进。**

位置：299 取友军 ATK 后打其前方；310 同时打相邻与前方；555 给友军 HP/Taunt 再打同一目标前方。可在四格显式位置、固定已知身体中做，不需整局模拟，但不能给每一步另选最大收益目标。

随机与 Look/Choose：随机对象按共同池平均；实际看见候选后才取允许的最佳选项。部分先看最高/最便宜，再随机/选择，不能用一个 random 布尔值替代顺序。

复制/返回/Transform/Erase：需保留基础/当前属性、Exact copy、非-DT、Silenced、身份和区域。989 Delay 的目标存活对象、910 unique COST、各种来源条件须查实际原文，不以 annotation `parsed` 放行。当前快照动作通常写 `Turn … into`，只搜索词 Transform 会错误得到0；实际这个表达子集为9。

**裁定障碍：**受伤沉默后的当前/最大HP、复制与跨区保留、平局选择器、同时触发队列存在独立未知。先实现明确字段与窄域转移，再把真正裁定不明的参数作为双版本，不应直接扩大自由定价。

## 结构解析与数值执行应分别计数

现有 V6 holdout 的16张 requested 有39个模块、12种 kind、9种 trigger；15 `parsed`、1 `partial`，结构校验通过并不表示每个模块可执行。已有独立复核指出：153手数门、658Generated过滤、984召唤覆写、812成功代价、989guard目标和部分选择器仍缺失或错误。这里仅复用这些已审线索，404的机制数来自快照全文，不来自119张旧 annotations 的代表性假设。

建议后续导出五个独立数字：

1. snapshot 家族命中卡数；
2. 完整结构解析卡数/片段数；
3. 全部所需状态在给定情境中绑定的模块数；
4. 通过数值转移与独立反例的模块数；
5. 整张文字、引用依赖和全部分支均可执行的卡数。

只有第5项可以进入完整条件分数。部分模块仍可展示自己的账本，但标题分数保留 null；条件部署可支付权重不同的均值，不能直接相互排名。不存在用“已认识Add/召唤”给96/65张自动赋分的捷径。

## 下一迭代可检查的完成条件

推荐先完成 P0 的有限字段与谓词，然后以 **固定属性/状态、固定引用召唤、双边/可选抽牌、手牌费用子集** 四条共用路径扩展。每一条至少使用未参与模板开发的卡和失败边界；禁止只检查某个具名成功案例。

完成时应保存冻结 snapshot/源码哈希、匹配的全部 ID、正反例和新增完整覆盖数。完整覆盖增量根据实际 unsupported 清单消失及执行检查计算，不能预先承诺“61属性卡＋65召唤卡”。参数仍由共同模型决定；语义提取只填机制、条件、数量、对象和证据，不提供价格、触发概率或为四张卡调整的权重。

## 可复算计数规则

所有正则只用于**盘点入口**，不能直接用于执行效果；动作句计数使用边界 `(?:^|[:.] )`，避免把 `After you summon...` 当成执行 Summon。匹配按不同 card_id 去重。主要口径如下：

```python
pool = [c for c in snapshot['cards']
        if c['card_type'] == 'monster'
        and c['pool_category'] == 'ordinary_non_token'
        and 4 <= c['cost'] <= 8]

# 不同卡数，不是动作次数；这些集合可能重叠。
add = r'\b[Aa]dd\b'                         # 96
summon = r'\b[Ss]ummon\b'                   # 65，含触发/引用用途
draw = r'\b[Dd]raw\b'                       # 33
attributes = r'\b(?:Give|Gain)\b[^.]*\b(?:ATK|HP)\b'  # 61
damage = r'\bDeal\b.*?\bDMG\b'             # 36
cost_delta = r'(?:COST [+-]\d+|[+-]\d+ COST|costs? \d+ less GOLD)'  # 45
fixed_add = r'(?:^|[:.] )Add (?:an? |\d+ )[A-Za-z][^.]*?\[#\d+\] to your hand\.'  # 25
fixed_summon = r'(?:^|[:.] )Summon (?:an? |\d+ )[A-Za-z][^.]*?\[#\d+\](?: for the opponent)?\.'  # 24
fixed_stats = r'(?:^|[:.] )(?:Give|Gain) [^.]*?[+-]\d+ (?:ATK|HP)(?:/\+\d+ HP)?\.'  # 19
selectors = r'\b(?:adjacent|front|leftmost|rightmost|highest|lowest|most expensive|cheapest|top)\b'  # 34
# Heal/Kill 按 re.I 全词计数，分别21/9；不能漏掉小写的后续动作。
```

完整简单模板的子集使用 fullmatch、容许前置主体 Haste/Dodge/Taunt/Armor；不删除 Need、Synergy、额外触发或后续句子。固定 Add 完整3张=42/219/885；Magic Summon完整4张=169/170/282/862；Dust Summon完整4张=108/112/235/426；简单 Draw完整3张=44/199/243。它们的引用依赖和主体状态仍需执行器支持，因此这是模板计数，尚非数值批准数。
