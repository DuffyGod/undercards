## 已确认的正确边界

- `premium` 计算特殊与普通路线的期望终态效用差，没有在该函数内再次加一个完整击杀奖金或第二次 Haste 攻击。两路初始身体和 Magic 后状态应相同。
- `optimal_declared_plan` 先确定一个提前计划，再对全部回应求期望，未对每个未知回应分别选最佳提前目标。`later_attack` 在回应发生后才选择行动，符合当前窗口的信息顺序。
- `trade` 保存双方攻击值后处理反伤，攻击者先死亡不会取消已经发生的另一方伤害。伤害实例消耗 Dodge，后续 chip 不会重用已经耗尽的 Dodge。
- 支付 chip／silence 分别检查 2／3G 余额，余额不足时不执行，也不凭空制造回应怪物。
- 死亡单位没有残留身体价值：离线核对 `body_value(6,0/-1/-10)` 均为 0；`utility` 也将非正 HP 送入零 HP 身体。

## 必须处理的规则与输入问题

### 1. 敌方 Taunt 没有约束攻击目标（高优先级）

`trade`、提前计划枚举和延后攻击枚举只检查目标存活，没有过滤敌方嘲讽。它们因而能把 Haste 的收益算在非法提前击杀上。

可复现输入：我方 4/5、Haste；敌方槽 0 为 **0/10 Taunt**，槽 1 为 **3/3 普通怪**；`enemy_face` 权重 1，敌方 0G，角色 aggro。

当前结果：`keyword_bundle.plan=1`，先攻击并击杀槽 1，剩下敌方 0 攻击者；`premium_model_gold=1.2`。本地规则要求先攻击嘲讽，槽 1 是非法目标。依当前仅一个攻击／一个回应的窗口，补齐嘲讽限制后，这个案例的纯 Haste 提前收益应为 0：提前与延后都不能移除 3/3 攻击者。

最低成本修正：共享 `legal_own_attack_targets`，在 `trade` 和两种计划枚举中使用；只要有存活且可指定的敌方 Taunt，怪物攻击只能选它们。目标过滤不能分别在几个入口重写。

### 2. 不支持的状态被静默丢弃，回应可指定性没有检查（高优先级）

`state` 只保留 Dodge／Armor／Taunt。输入 `{transparency: True, darkspawn: True}` 会静默变成普通身体；随后 `reply(...,'chip')` 花 2G 对它造成 2 点伤害。实际 Transparency 禁止指定，Darkspawn 禁止法术指定并免疫法术伤害。

这不是要求马上实现全部防护。最便宜的修正是显式声明受支持状态键；遇到 Charge、Transparency、Darkspawn、Invulnerable、DT 沉默免疫等未支持机制时返回部分支持／拒绝完整估值，禁止当作不存在。若把 chip 定义成法术，应明确动作类型和合法目标；若只是抽象伤害实例，名称与输出须说明不能代表那些法术回应。

敌方身体输入会保留额外状态字段，但指定规则同样未执行。因此仅校验我方 `statuses` 不够，敌方身体也要检查支持边界。

### 3. 回应配置可被静默误读，NaN 可进入分数（高优先级）

离线反例：

```python
weights = {'misspelled_silence': 1}  # 被当作无回应，正常返回 premium=0
weights = {'none': float('nan')}    # 通过检查，返回 NaN
```

当前只检查权重和与负数；NaN 的比较结果使这些检查失效，未知事件名称则进入 `reply` 的无操作路径。

最低成本修正：验证事件键属于声明集合；每个权重必须是有限的非布尔数值、非负；总和为 1。对身体数值、Dodge 次数、金币及已存在敌方 ID 的输入也做边界验证。配置错误不能与“回应当下不可支付，所以没执行”混在一起。

## 接入统一账本前的两个重要限制

### 4. Magic 后的世界与身体生命周期必须共同绑定，不能只加一个关键词差额

当前没有上层调用者：检索只发现独立工具与测试。`premium` 的初始 `enemy_bodies` 是调用者提供的原样列表，它无法知道 Magic 是否已经杀死或削弱这些敌怪。若先在外层计 Magic 的移除收益、却再把 Magic 前的敌怪传给本模块，它们会再次参与攻击、打脸和击杀收益。这是接入时的重复计价风险，目前尚不能断言已有流水线发生该错误。

最低成本修正：要求明确的 `post_magic_state`，包括已移除目标、当前伤害、增益、占位和脸伤。外层只加 `paired_premium`，不能再加同一次交换的 Haste／Dodge／击杀独立奖金。新增一个通用回归例：Magic 已移除唯一敌怪时，该敌怪不能在后续窗口复活攻击。

同理，`synthetic_paid_keyword_silence` 只清除三个状态、保留全部 Magic 调整的 ATK/HP。这是受限的“关键词清除”反事实，不能代表真实沉默对自身持续成长的删除。攻击、死亡与 Dust 也没有共同结算；不能把固定 Dust 兑现先验与本模块改变后的死亡路径直接当作独立收益相加。

可以继续采用低成本局部模型：每个响应分支共用同一份候选基础身体／可撤销增益／死亡事件账本；不需要完整服务器执行器。尚未共用时，应将这些组合保留为部分支持。

### 5. 反应成本和 Haste 频率只能按当前窄窗口解释

`utility` 用 `-0.5 * enemy_gold` 表示对手剩余资源的不利；付费回应因此可能给我方产生 **对手资源耗损的加权效用**。它不是我方真正收到金币。两路相同支付会取消；当一条路径已无合法候选可回应时，支付可以不同。结果的名称和账本应明确这种含义，不能同时再加一次“逼对方交解”的金币收益。

此外，敌方只执行一个最强现存身体的行动，未描述攻击是否可用、其他我方 Taunt、回应牌的抽到／保留机会或新回合收入；chip／silence 的 2／3G 是合成动作成本，并非真实完整回应卡的转化率。当前作为声明情境成立，但不能宣称已衡量特定 Soul 或实际卡组的解场质量。

Haste 提前与普通延后共享最多一次我方攻击，没有下一回合 Haste 单位的第二次正常攻击，也没有时间折价。现有无回应测试中 Haste 增量为 0，表示“同一攻击仅换时间，且该窗口没有对时间赋值”，不是证明 Haste 在空回应环境没有价值。

最低成本修正：保持一次交换，不扩建完整对局；将输出命名为 `first_contact_increment`，分别显示身体、我方 HP、对手现金三项差分及动作时点。需要衡量攻击频率时，增加明确的独立下一次攻击机会／时间窗口项，并检查没有再计同一次交换，而非悄悄把它解释为全部关键词价值。

## 建议增加的最低成本回归检查

1. 上述 Taunt 阻挡例：提前和延后都拒绝非法普通目标。
2. 未支持状态、拼错事件、NaN 权重必须显式失败／部分支持。
3. Magic 已移除敌怪，后续不再选它或让它攻击；两个反事实保持同一 Magic 世界。
4. 纯 Dodge 被首个伤害消费后不在下一实例重复使用；独立固定“Armor 与 Dodge 的先后未核实”边界，不用测试替代实际规则裁定。
5. 相同付费响应的现金项在两路差分中恰好抵消；不同支付单独显示为对手资源效用，而非我方到账。
6. 早期计划对全部隐藏回应保持相同；延后决策只依赖已经观察到的状态，不读取下一步隐藏结果。

初版审查结论：成对差分和信息结构比独立关键词奖金更稳健，死亡身体处理正确。0.1.1已修关键目标与配置问题；继续补齐值域验证，再用明确的 Magic／响应状态合同接入账本。当前不能独立代表完整关键词或全牌 Value。

## 下一版两段攻击窗口的审查意见

根智能体提出：现在 Haste 可选一次怪物攻击 → 相同对手回应 → 下一己方回合存活单位可选一次正常攻击（可攻击玩家）。普通主体只有后一段。这个扩展能表达攻击频率，不需要完整对局；用共同终态 F 差分，没有自动产生“攻击次数翻倍，所以身体计两遍”的问题。

要求：

- 两路下一回合都允许不攻击、合法怪物目标、合法玩家目标；敌方存活 Taunt 禁止打脸。零攻击、Disarmed 等也不能凭默认正常身体获得行动；未支持状态仍需拒绝。
- 第一段行动必须在未知回应前固定；第二段只能利用回应后已观察状态。不能对未来回应逐个挑不同的第一段目标。
- 应保存双方实际玩家 HP 并处理终局。第一段斩杀、回应令我方玩家死亡后必须立即停止，不得继续生成下一回合收益。仅累计 hp_delta 不能判定这一点。
- Magic 后世界、成长来源、存活／死亡和回应费用要同源；终态身体、玩家 HP 与对手现金已经计价时，不再加独立击杀／额外攻击奖金。
- 真实 Silence 若未实现持续数值清理，应继续叫关键词清除情境，不能通过扩大攻击窗口改变其含义。

建议的小型通用检验：我方2/5、敌方两只1/1、无回应。Haste可前后各击杀一只，普通只能进行下一回合一次攻击；但需允许普通选择玩家，比较全部合法路线而不是强制普通去击杀。对照无敌怪局面：Haste当前不能打脸，两路都只有下一回合的正常玩家攻击，纯Haste增量应为0。另加入敌方最后一只Taunt在第一段死亡后，下一段才开放玩家目标的测试。
