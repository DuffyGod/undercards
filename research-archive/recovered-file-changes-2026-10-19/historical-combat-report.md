## 现在能比较什么

原生1–10G普通非衍生怪物分母仍为644。相同输入下完整正文编译支持从104增至108，无减少；新增Knight Knight17、MTT Fountain163、Normal NPC291、Plated Pipe526。这是语法和运行框架支持，不代表四卡的每个场景都已闭合：没有确定的规则仍会保留未知。

本批实际重算4/5/6/9G中全部59张当前可编译候选，各四场；另做四张事件卡的声明规则、保留身材与关键词但移除事件的同体对照，以及“同一本体已攻击并存活”的用途。共300条主曲线，250条采样全闭合；其中236条默认规则原生比较有186条闭合、50条未知，64条声明规则及对照用途曲线全部采样闭合。27条定向数值反事实中22条闭合、5条未知。

正式核心搜索2076次，pilot199次另计；公共接口、完整向量和独立程序另列，不把重复测试凑作独立战斗。327个不同输入／卡源／用途组合、1100个采样下界、649个可行联合报价均检查来源和根目标坐标。旧55张候选的220条同输入曲线实际重算后，最大生存、已知／可行状态、采样点与前沿数值全部不变，证据见 `cross-version-verification.json`。

公共实验条件：当前己15/30HP、敌30/30HP，候选已在手、当前现金等于原生费用；下回合+5G并从已知顺序库抽Ice Cap（3G、3/1 Charge），敌方手牌已知为空、无新收入抽牌。四阶段为当前我方、敌方、下回合我方、敌方。公开场面为空、单个2/3、三个2/3、单个6/8。双方枚举攻击顺序／目标／停手；我方可早出、晚出或一直持有，真实付款。未知敌手、牌库分布、SOUL／神器等没有被本实验覆盖。

## 可以直接核对的差异

下面每对数字为同一策略的“己HP下界／敌HP上界”，各行资源和用途固定。不同前沿点可以需要不同策略，不能拼接。默认规则的已知结果只说明在当前枚举的语义解释中物理状态相同，不是服务器规则已验证。

| 同费原生比较：单个2/3、纯生存与压力 | 联合前沿（默认规则） |
|---|---|
| Jerry，5G | 15／23 |
| Aaron，5G | 13／24；11／21 |
| MTT Fountain，5G | 17／27；13／25 |
| Long Sink，5G | 19／30；15／23 |
| Carbed，5G | 13／25；11／22 |

这不是五张卡的全局排序。在三个2/3下，Jerry仍为15／23，Long Sink变为12／30或10／27，Fountain默认保留未知。若只在Jerry与Long Sink中选择、只优化己HP、两类公开场景在出牌前可辨认，宽场比例p下的保证分别为15和19−7p：切换点p=4/7。没有推断真实p；候选固定在观察场面之前，不能看到场面后换卡。

因果对照只移除事件文字，保留原生费用、A/H与Haste／Armor。具体结论如下：

| 原生与同体对照 | 原生 | 移除事件 | 适用范围 |
|---|---|---|---|
| Fountain，单个2/3 | 17／27；13／25 | 13／27；11／25 | 原生默认已知；真实承伤与付费Ice Cap参与策略，不是给Haste固定加分 |
| Normal NPC，单个2/3 | 15／27；11／23 | 15／23 | **声明it=self**；当前Haste攻击后的麻痹阻断下回合攻击，默认指代未裁定故未知 |
| Plated Pipe，三个2/3，纯生存与压力 | 7／29；3／22 | 7／30；3／22 | 原生默认该场闭合；同一触发不在所有策略中都有增量 |
| Knight Knight，单个6/8，要求本体已攻击且存活 | 9／30；3／22 | 9／30；3／25 | **声明按伤害包治疗**；只看纯玩家HP时两者前沿相同，本体用途才暴露压力差异 |

Knight的差异有直接打法含义：敌方若两次攻击本体，原生可以在中间主动攻击玩家后回血，保住原本会被第二击杀死的实体；同体对照必须花攻击／Ice Cap处理敌体，失去部分打脸空间。Fountain的治疗发生在实际伤害事件后，不能把一次交换中的伤害和另一路的治疗最大值相加。

定向反例也公开保留：声明规则下，Fountain面对同为3HP但ATK为1、3、4、5的单敌，纯生存保证依次16、18、19、15；移除事件为14、12、11、10。伤害提高先增加可回收治疗，跨过本体存活门槛后下降。因此“敌方ATK更高必定更赚”和“固定回血关键词加分”都被淘汰。ATK≥3的原生默认仍可能因致死规则分歧而未知，声明值不得替代默认结论。Pipe面对单敌ATK1、3、5，声明规则与无事件对照的整组采样前沿相同；触发文字存在不保证在最坏回应下产生增量。

## 通用机制改动与反事实

伤害事件现在携带实际来源、原始量、减免后量、实际损血和该次受伤后的存活。不可变pending事件随物理实体进入缓存键，结算后消费一次。攻击后钩子放在直接同时交换之后、普通Dust之前；双方、法术、普通Magic与已支持的伤害扩展共用这一流程。

旧核把HP截断到0，不能据此把过量伤害直接解释为“DMG dealt/taken”。新模块用同一纯伤害原语的高HP计量probe保留减免后量，probe不是真实事件、不改变状态、不再触发回调。此证明依赖当前原语不读取目标受伤／HP谓词；若未来加入这类减免，应重新审查。包量解释不同但回血上限使完整结果相同时可闭合；否则未知。Dodge／Armor仍使用旧核既有且已公开的顺序假设，没有新添服务器证据。

`combat_event_rules`可明确声明以下假设；省略均为unknown：

| 参数 | 可选明确假设 |
|---|---|
| damage_measure | hp_loss / effective |
| lethal_received | trigger / no_trigger |
| zero_received | trigger / no_trigger |
| attack_paralyze_it | self / target |
| dead_attacker | trigger / no_trigger |

同一事件的不确定解释及回调次序不能由施放者挑选；当前只有完整物理状态一致才接受。有相互致死的两张Pipe时，终局次序不同会保持未知。攻击／受伤事件与实际Dust竞争仍拒绝；未闭合的召唤孩子回调不会静默降为普通身体。Silence清除后续事件，不撤回既有治疗。旧有限治疗上界证书与位置商证书拒绝新事件域，避免把新回血遗漏成0。

## 独立验证与可追溯性

独立四阶段有限对战程序只用标准库，不导入生产伤害／搜索／评分代码。读取80个四事件家族主实验与27个敏感度文件后，对94条有已知结果曲线验证了94个生存锚点、217个联合保证及217个“再多1压力不可保证”的严格上界、107个不可行采样下界：全部匹配。13条未知曲线明确跳过，没有填零。共635独立约束查询、累计65692个独立状态。它检验的是一个公开声明的具体规则世界，不能证明未裁定服务器语义完整，也不把其余233条普通候选曲线写成独立核验证。

另有13个同值直接交换、6个默认应未知的分歧、3个NPC时钟匹配；13项真实付费法术／Magic／召唤拒绝路径检查；四张卡alpha-beta与穷举完整向量一致；直接入口、公共API和实际CLI完整JSON一致。初期手算、schema错误和旧测试夹具失效均保留在development-history及初始失败回归中。

回归覆盖734项：本轮当前源码694项通过，40项递归源同复用。实际执行709次：初跑694中只有一个“Knight17仍应未知”的旧夹具断言失败；修正为仍未知的Moldbygg19后，该整个15项模块重跑通过。其余679项通过测试的源码未变。原失败没有改写成通过；不再重复跑全部套件。公共报告按实际测试模块依赖绑定，原包含运行器的完整收据另外存档。离线页面执行720种控件组合、核对1962条原始链接；未做浏览器布局检查。
